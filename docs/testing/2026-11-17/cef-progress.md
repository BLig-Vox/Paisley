- Build supervisor verifies a kernel 2 GiB limit and zero build swap. A cached WebKit build passed at 1,794 MiB. CEF check passed at 1,794 MiB. CEF native test build passed at 899.75 MiB after dependencies were cached (initial native build 1,747 MiB). These are not clean-build benchmarks.
- Native CEF lifecycle suite passed on Bot Screen: 12 close/reopen cycles, edited form state retained in the surviving tab, same-profile HttpOnly cookie sharing, separate private-window cookie isolation. Whole process tree peaked at 1,022.09 MiB during this suite, which includes two independent private CEF engines; this is not a one-tab website benchmark.
- Five tab residency policy tests watched fail (four failed, one already passed) against a no-op, then all five passed after implementation. They protect active, dirty, unknown, stale, busy and non-reloadable pages, honor idle grace, and select LRU victims. Live browser integration still pending.
- Ruling: Retain in-place uncommitted work and do not discard the previous WebKit fixes. The installed browser remains unchanged until CEF parity and native tests pass.
- Ruling: User approved only a temporary no-sandbox Bot Screen test. Its constrained root account rejects both runuser/setgroups and setpriv/setuid (Operation not permitted). An explicit environment flag plus the separate cef-test-support feature and a debug build are required. Normal builds do not automatically disable the sandbox. This exception does not validate sandbox behavior on an ordinary Linux desktop.
- Ruling: Remove upstream key-press logging from the GTK adapter so typed text is not written to diagnostic logs.
- Live residency passed on native Bot Screen: eight pages each touch 32 MiB of JS heap; five inactive clean tabs slept, active and edited-form tabs stayed resident. Whole-browser PSS dropped 1,070→840 MiB in the crash-recovery suite. Sleeping tab restored and the protected draft remained. Native timing is artificially aged only in tests; production grace remains 5 min normally / 30 s under pressure.
- Native downloads passed: cookie-authenticated fixture, visible byte counts while paused, resume after source tab closes, exact PNG/ZIP/PDF/UTF-8 TXT bytes, staged atomic publication and staging cleanup. Source-tab destruction initially stopped CEF download events. Fix retires that page to hidden 1×1 about:blank until its transfers terminate, then closes it.
- Engine-crash regression reproduced a disconnected profile service owner after the page recovered. Generation-guarded profile reconnection fixed it; the native test now forces only its owned engine to exit, restores a page and receives profile stats again. No owned processes remained after the green suite.
- Native favicon fixture loaded successfully. Caching now happens on favicon changes rather than every title/loading/control update.
- CEF ShowDevTools ignores windowless settings and opens a native Chrome window. Initial title-only test was insufficient; stronger painted-frame assertion failed and Bot Screen showed the empty right pane plus a separate native window. Investigating a private token-gated loopback CDP relay to render the bundled frontend in a regular OSR view. Do not mark inspector parity complete yet. Upstream source: https://github.com/chromiumembedded/cef/blob/master/libcef/browser/chrome/chrome_browser_delegate.cc and issue https://github.com/chromiumembedded/cef/issues/4353 .
- Inspector relay succeeded on Bot Screen: the bundled `devtools_app.html` paints inside the right GTK pane, displays the fixture DOM (verified by traversing frontend shadow DOM), and closes without retaining its native view or loopback listener. The inspected page still executes script afterward. The relay binds only 127.0.0.1, requires a fresh 256-bit path token and DevTools/null Origin, rejects a wrong-token WebSocket upgrade in the native harness, bounds each direction to 4 MiB / 64 messages, and drops its observer/thread with the frontend. No global Chromium remote-debugging port is enabled. The earlier ShowDevTools implementation was removed.
- Native test runner now selects the newest ELF test binary and records its SHA-256. A dependency change had changed Cargo's output hash, leaving a previous binary selected; rerunning after correcting selection confirmed the relay implementation, not the native-popup attempt.

## Dialogs, diagnostics and public websites

- Script dialog test first failed because CEF OSR's default alert implementation needs a native parent handle. Added one native pending callback per page, bounded text, correlated responses, reset/close cancellation and a GTK window with weak owners. Native alert, confirm cancellation, Japanese/emoji prompt round trip, weak-window release and closing a tab with a pending prompt passed; exit 0 and no owned processes remained. Peak sampled PSS: 728.76 MiB. Native beforeunload is routed as confirmation; it has not yet received a dedicated interaction test.
- Test compilation with `--features cef` exposed the native harness importing `terminate_for_test` without enabling adapter test support. The harness and entry point now require `cef-test-support`; ordinary CEF binary tests compile and run without that feature.
- Two completion/error diagnostic vectors were unbounded. Their new test failed with 10,000 retained entries; after bounding the shared append helper, only the latest 200 remain. All 12 CEF binary unit tests passed.
- Regression tests: 54 root library tests, 12 transport tests, 12 CEF binary unit tests and 27 Python tests passed. Build/test commands all used the kernel-enforced 2 GiB cap and zero build swap. The root library run peaked at 1793.8 MiB; these are cached build results.
- Latest YouTube playback test passed after a real mouse click on Play: video time advanced 0.091036→5.089685, paused false, no media error and no ad. Peak whole-tree sampled PSS 1383.36 MiB; exit 0, no owned processes remained. This is a short WebM-compatible playback check, not codec/DRM certification or a long soak.
- Eight unauthenticated public sites loaded in the same private profile: GitHub, Gmail, Google, YouTube, Rust, Wikipedia, docs.rs and example.com. Whole-tree PSS at the measurement stages: eight resident 1642 MiB → five eligible inactive tabs slept 1142 MiB → close back to one tab 1023 MiB. Peak sampled PSS across navigation: 1857.98 MiB. Exit 0, no owned processes remained. Tests artificially age idle timestamps; production grace is unchanged. Gmail was signed out. These figures are whole-browser totals, not per-tab usage or a comparison against the old release.

Ruling: Keep the installed/default WebKit browser and published crate unchanged. Core CEF behavior has native evidence, but permission/notification integration, real opener-preserving popups, select-popup painting, IME and runtime packaging still need work. The approved root no-sandbox exception remains temporary test-only; secure non-root deployment cannot be validated in the current constrained Bot Screen. Cost of prematurely promoting it would be lost browser functionality or an unusable/unsafe installation.

## Authentication and file input checkpoint

- HTTP Basic challenge first failed to reach GTK. Wiring RequestHandler alone still opened Chrome's detached Sign in window. CEF requires `disable-chrome-login-prompt` to delegate these challenges to GetAuthCredentials (upstream: https://github.com/chromiumembedded/cef/issues/3603). With that switch, native HTTP Basic credentials were accepted, both fulfilled and abandoned prompts released their GTK windows, and the engine exited without owned processes remaining. Username/password contents are not logged or stored by the GTK bridge. Proxy and Digest challenges use the same callback but have not received separate fixtures.
- File input first opened CEF's independent native chooser rather than the GTK bridge. Added CEF DialogHandler, bounded filter/path metadata, correlated file callbacks, owner cancellation and all four native chooser modes. A real click opened the GTK picker; Bot Screen selected sample.txt; the page read and exactly matched its Japanese/Chinese/emoji UTF-8 contents. A second chooser was cancelled by closing its tab.
- The first asynchronous GtkFileDialog implementation emitted GLib/GIO criticals on immediate cancellation, even after waiting for its callback. GTK 4.14's portal hide path clears `data->connection` while its pending OpenFile callback calls finish with that connection (https://github.com/GNOME/gtk/blob/4.14.5/gtk/gtkfilechoosernativeportal.c). A log assertion reproduced the failure. An owned GtkFileChooserDialog removed that portal lifecycle from this Linux desktop path; rerun passed with no GIO critical and no remaining owned processes. Open/multiple/folder/save are wired, but the actual native fixture exercised only single-file open and owner cancellation.

Ruling: Use the owned GTK file chooser for CEF desktop file inputs instead of adding a delay around the GTK portal race. It has weak owners and synchronous window teardown. Cost: GtkFileChooserDialog is deprecated within GTK4 and does not provide Flatpak portal grants; a future sandboxed package needs an explicit portal implementation or a fixed toolkit path. This branch does not claim Flatpak support.

## Select popups and combined native checkpoint

- Popup frame rendering was absent: the select fixture failed its painted-popup assertion. Added a second latest-frame mailbox slot, independent of main-page frames, and fair delivery between the two. Its red test showed a popup replacing the main frame; all 14 transport tests passed after implementation. Ordered control events retain their separate byte/count limits.
- CEF popup visibility/position and RGBA frames now reach GTK, are clipped/composited above the main page, and are released when hidden. Serial numbers reject queued frames from dismissed/replaced popups. Only one latest auxiliary frame is retained per view. Main-frame pixel transport is unchanged.
- An initial synthetic click occurred before the new tab had painted at its current allocated size; native traces showed show→hide with no popup paint. A real Bot Screen click painted the Unicode menu and completed all 20 cycles. Waiting for a mapped, correctly sized main frame and taking GTK focus fixed the test driver. A fresh run then passed unaided, including selecting the Japanese/Chinese/emoji option and 20 reopen/Escape cycles. Edge-of-window positioning and fractional/high-DPI scaling remain unverified.
- The combined native suite passed with diagnostics for popup tracing disabled: 60 tab cycles, form retention, cookie/profile isolation, residency/restore, authenticated downloads and closed source tab, visible navigation failure, site-data clearing, strict cookie/WebRTC policy, right-docked inspector, script dialogs, HTTP Basic auth, select menu interaction, **12 immediate file-chooser owner-close cycles** and engine-crash recovery. Exit 0, no owned processes remained, no GLib/GIO criticals. PSS across 12/24/36/48/60 closures: 674/682/669/683/683 MiB; populated eight-tab fixture 1106→875 MiB after five eligible tabs slept. Peak sampled PSS: 1105.49 MiB. This is bounded fixture evidence, not a proof that all websites or long sessions are leak free.
- The native supervisor now classifies GLib/GIO critical diagnostics as failures even if the executable returns 0. Its classifier test was red before implementation; all 29 Python regressions passed afterward.

Remaining before promotion: CEF website permission/notification integration, opener-preserving popups, IME/high-DPI verification, runtime/Cargo packaging and a fresh whole-change review. Installed/default browser and published crates remain unchanged.


## 0.2.0-alpha.1 publication checkpoint

The user explicitly requested Cargo and GitHub publication. Release scope is an honest source prerelease: WebKitGTK remains default; CEF is opt-in, with its runtime and functionality limits in docs/CEF_PRERELEASE.md. This supersedes the earlier hold on publishing the crate, not the hold on making CEF the installed/default browser.

A fresh whole-change review identified path-only registry dependencies, a root source reference into a nested package, missing runtime packaging, terminal partial retention and HiDPI scaling. Registry dependencies now have exact support-crate versions; root residency uses a real dependency. Failed/cancelled/interrupted terminal handling takes and removes its private staging leaf outside the UI borrow. The cleanup regression was observed failing before the fix and passing afterwards (13 CEF binary tests). HiDPI, runtime installation and remaining permissions/notifications are explicitly not claimed complete. Follow-up review found no further must-fix blocker for this narrowed prerelease, conditional on actual archive verification.

The fresh combined native run used binary SHA256 8ba817d07df7986a115afe0379e114b4641816377eb40e9e3559f24e93146770: exit 0, runtime_criticals [], no owned processes left. Peak sampled whole-process PSS 1357.52 MiB. Sixty tab cycles completed; 12/24/36/48 cycle checkpoints were 674/678/679/679 MiB. The same functional suite covered residency, transfer pause/closed source, dialogs, file-owner cancellation, dropdowns, privacy, inspector and crash recovery. GTK layout diagnostics and unavailable system D-Bus services remain in fixture logs; absence of GLib criticals is not an assertion that stderr was empty.

Transport's 14 tests passed both in the checkout and from its extracted crate archive. Python's 29 tests passed. The latest native-test build used 750.10 MiB cgroup peak under the enforced 2 GiB cap, swap 0, zero OOM events. Archive verification and final publication results are recorded separately in the release verification file.
